# 五、H743 开发特别注意事项

STM32H743 比 F1/F4 更强，但坑也更多。

------

## 1. 注意 Cache 和 DMA 的问题

H7 有：

```
I-Cache
D-Cache
```

如果你用 DMA，比如：

```
ADC + DMA
UART + DMA
SPI + DMA
ETH DMA
SDMMC DMA
```

可能会遇到：

```
DMA明明接收了，但CPU看到的数据不对
CPU改了数据，但DMA发出去的还是旧数据
```

原因通常是：

```
D-Cache缓存一致性问题
```

简单理解：

```
CPU看到的是缓存里的数据
DMA访问的是内存里的数据
两边可能不同步
```

解决方式一般有：

```
关闭 D-Cache
或者使用 Cache clean / invalidate
或者把 DMA buffer 放到不缓存区域
```

新手阶段，如果只是普通 GPIO、串口阻塞发送、定时器，不一定马上碰到这个问题。

但是你一用 DMA，就要注意。

------

## 2. 注意 H7 的内存区域

H743 内存不是简单一整块 SRAM。

它有不同 RAM 区域，比如：

```
DTCM RAM
AXI SRAM
SRAM1
SRAM2
SRAM3
SRAM4
Backup SRAM
```

注意：

```
有些 DMA 不能访问某些内存区域
```

比如你把 DMA buffer 放到 DTCM，可能 DMA 访问不到。

所以 H7 上经常会出现：

```
代码没错
DMA就是不工作
```

结果是 buffer 放错内存区域。

------

## 3. 注意时钟树比 F1/F4 复杂很多

H743 有多个时钟域：

```
D1
D2
D3
```

还有多个 PLL：

```
PLL1
PLL2
PLL3
```

所以你配置时钟时，不要凭感觉。

建议先用 CubeMX 自动配。

常见目标：

```
SYSCLK = 400MHz 或 480MHz
HCLK 根据配置
APB1/APB2/APB3/APB4 分频
```

如果外设频率不对，比如串口波特率异常、定时器频率不对，第一时间看：

```
Clock Configuration
```

------

## 4. 注意电源配置影响主频

H743 想跑高频，需要正确配置：

```
电源调压等级
Voltage Scale
```

常见是：

```
PWR_REGULATOR_VOLTAGE_SCALE1
```

有些高频还涉及 VOS0。

如果电源等级不对，可能：

```
频率上不去
程序异常
系统不稳定
```

这个通常 CubeMX 会帮你配，但你要知道它存在。

------

## 5. 注意 Flash ART / Cache / MPU

H7 性能高，但是系统复杂。

常见涉及：

```
ICache
DCache
MPU
Flash latency
```

如果你只是普通开发：

```
先用 CubeMX 默认配置
不要乱改 MPU
不要一开始就手动调 Cache
```

等用到 DMA、ETH、LCD、SDRAM 时再深入。

------

## 6. 注意 GPIO 速度和电平

GPIO 配置里有：

```
Low Speed
Medium Speed
High Speed
Very High Speed
```

不是所有 IO 都无脑 Very High。

普通 LED、按键：

```
Low Speed
```

SPI、SDMMC、FMC、高速总线：

```
High / Very High
```

速度越高，边沿越陡，干扰也可能更大。

------

## 7. 注意串口调试非常重要

快速上手建议你第一个工程就加：

```
printf 重定向到 USART
```

以后调试就方便很多：

```
printf("hello h743\r\n");
printf("adc=%d\r\n", adc_value);
printf("state=%d\r\n", state);
```

没有串口打印，调试会很痛苦。

# 八、开发时遇到问题应该怎么排查？

你可以按这个顺序排查：

```
1. 原理图：引脚接对了吗？
2. Datasheet：这个引脚支持这个复用功能吗？
3. CubeMX：外设模式、引脚、时钟配对了吗？
4. 代码：初始化函数调用了吗？
```

先查：

```
TX/RX 引脚是不是接反？
CubeMX 配的是不是同一个 USART？
波特率是不是一致？
有没有接 USB转串口？
GPIO Alternate Function 对不对？
有没有调用 MX_USARTx_UART_Init？
```
