# STM32H743 参考手册精华笔记：时钟 + DMA/Cache 坑点

## 1. 参考手册主要看什么？

参考手册 RM0433 不是用来查“某个引脚在哪”的，那个看数据手册；参考手册主要用来看 **芯片内部模块怎么工作、寄存器怎么配置、总线/时钟/DMA/Cache 怎么组织**。它覆盖 STM32H742、STM32H743/753、STM32H750 系列的存储器和外设使用信息。

你现在快速上手开发，参考手册重点看这几块：

| 模块                        | 重点                                           |
| --------------------------- | ---------------------------------------------- |
| Memory and bus architecture | 搞清楚 SRAM、DTCM、AXI SRAM、DMA 能不能访问    |
| RCC                         | 搞清楚系统时钟、PLL、外设时钟来源              |
| DMA / DMAMUX / BDMA / MDMA  | 搞清楚哪个 DMA 能搬哪里的数据                  |
| Cache / MPU 相关内容        | 搞清楚为什么 DMA 数据会“明明传了但读不到/读错” |

------

## 2. 时钟 RCC：重点不是背寄存器，而是理解“时钟树”

STM32H743 的时钟比 F103 复杂很多，核心原因是它不只是一个简单的 HCLK、PCLK，而是分成多个 **时钟域 Domain**。

可以简单理解成：

```
外部/内部时钟源
    ↓
PLL 倍频
    ↓
系统时钟 SYSCLK
    ↓
D1 / D2 / D3 各个时钟域
    ↓
AHB / APB 总线时钟
    ↓
具体外设内核时钟 Kernel Clock
```

参考手册第 8 章 RCC 里面重点包含：时钟源、PLL、系统时钟、Kernel Clock、外设时钟门控、总线时钟门控等内容。目录中 RCC 从第 8 章开始，里面明确包含 Oscillators、PLL、System clock、Kernel clock selection、Peripheral clock gating 等部分。

------

## 3. 时钟需要重点理解的几个概念

### 3.1 时钟源

常见时钟源有：

| 名称 | 含义                           |
| ---- | ------------------------------ |
| HSI  | 内部高速 RC 时钟               |
| HSE  | 外部高速晶振                   |
| CSI  | 内部低功耗时钟                 |
| LSI  | 内部低速时钟，常给 IWDG        |
| LSE  | 外部 32.768 kHz 晶振，常给 RTC |

开发时最常见的是：

```
HSE → PLL1 → SYSCLK
```

也就是用外部晶振作为输入，通过 PLL 倍频到较高主频。

------

### 3.2 PLL：用来倍频，不是外设本身

PLL 可以理解成“时钟放大器”。

比如外部晶振 25 MHz，芯片不能直接跑 400 MHz 或 480 MHz，就需要 PLL 倍频。

在 STM32H743 里，不止一个 PLL：

| PLL  | 常见用途                            |
| ---- | ----------------------------------- |
| PLL1 | 主系统时钟 SYSCLK                   |
| PLL2 | 某些高速外设，比如 ADC、SPI、FMC 等 |
| PLL3 | 某些外设，比如 USB、SAI、SDMMC 等   |

注意：具体外设用哪个 PLL，要看 RCC 的 **Kernel Clock Selection**，不要凭感觉。

------

### 3.3 SYSCLK、HCLK、PCLK 的关系

可以这样记：

```
SYSCLK：系统总时钟来源
HCLK：AHB 总线时钟
PCLK：APB 总线时钟
```

它们不是同一个东西。

例如：

```
SYSCLK = 400 MHz
HCLK = 200 MHz
PCLK1 = 100 MHz
PCLK2 = 100 MHz
```

也就是说，CPU 主频高，不代表所有外设都跑这么快。

------

### 3.4 外设时钟有两层：总线时钟 + 内核时钟

这是 STM32H7 很容易混乱的点。

一个外设能正常工作，通常需要两类时钟：

```
1. 总线时钟：让 CPU 能访问这个外设寄存器
2. Kernel Clock：让外设内部功能真正运行
```

比如 USART、SPI、ADC、SDMMC 等外设，可能不仅要打开 RCC_APBxENR 或 RCC_AHBxENR，还要选择它自己的 Kernel Clock。

参考手册中也说明，复位后很多外设和部分存储器的时钟默认关闭，如果要使用某个模块，软件需要先通过 RCC_AHBxENR 或 RCC_APBxENR 打开对应时钟。

所以你以后看到：

```
__HAL_RCC_USART1_CLK_ENABLE();
```

它解决的是“外设挂在哪条总线上的访问时钟”。

但如果外设还需要独立内核时钟，还要在 CubeMX 或 RCC 配置里选它的 Clock Source。

------

## 4. H743 的内存和总线结构：DMA/Cache 坑点的根源

STM32H743 不是所有 RAM 都一样。

常见内存大概是：

| 内存区域  | 地址范围        | 特点                            |
| --------- | --------------- | ------------------------------- |
| ITCM      | 0x00000000 附近 | CPU 取指快                      |
| DTCM      | 0x20000000      | CPU 访问快，但很多 DMA 不能访问 |
| AXI SRAM  | 0x24000000      | DMA 常用，性能好                |
| SRAM1/2/3 | 0x30000000 起   | D2 域 SRAM，DMA1/DMA2 常用      |
| SRAM4     | 0x38000000      | D3 域 SRAM，BDMA 常用           |

参考手册的 Memory map 中列出了 DTCM、AXI SRAM、SRAM1/2/3、SRAM4 等地址分布，例如 DTCM 在 0x20000000，AXI SRAM 在 0x24000000，SRAM1/2/3 在 0x30000000 起，SRAM4 在 0x38000000。

------

## 5. 最大坑点 1：DMA 不能随便访问所有内存

这是 STM32H743 最重要的坑之一。

很多人习惯在 F103/F407 上这样写：

```
uint8_t rx_buf[1024];
HAL_UART_Receive_DMA(&huart1, rx_buf, 1024);
```

到了 H743 可能就出问题。

原因是：
**变量放在哪块 RAM，会影响 DMA 能不能访问。**

参考手册的总线互连表显示，不同 DMA、CPU、外设访问不同内存的能力不一样；其中 DMA1/DMA2 不能访问 ITCM 和 DTCM。

所以最关键结论是：

```
不要把普通 DMA 缓冲区放到 DTCM。
```

也就是说，这种写法有风险：

```
uint8_t dma_buf[1024];
```

因为它可能被链接脚本放进 DTCM。

更推荐 DMA Buffer 放到：

```
AXI SRAM：0x24000000
SRAM1/2/3：0x30000000 起
```

------

## 6. 最大坑点 2：DTCM CPU 很快，但 DMA1/DMA2 不能用

DTCM 的优点是 CPU 访问很快，适合放：

```
普通变量
算法中间变量
栈
对实时性要求高、只给 CPU 用的数据
```

但是它不适合放：

```
UART DMA 接收缓冲区
SPI DMA 发送/接收缓冲区
ADC DMA 采样数组
SDMMC DMA 缓冲区
以太网 DMA 描述符
USB DMA 缓冲区
```

因为普通 DMA 访问不到 DTCM。

参考手册里写到，DMA1 和 DMA2 有 memory bus 和 peripheral bus，它们通过系统总线能访问大多数内部存储器，但 **不包括 ITCM 和 DTCM**。

一句话记：

```
DTCM 给 CPU 用很爽，但给 DMA 用很危险。
```

------

## 7. 最大坑点 3：Cache 开启后，DMA 数据可能“不一致”

STM32H743 是 Cortex-M7，带 L1 Cache。系统结构图里也能看到 Cortex-M7 旁边有 L1-Cache。

这会带来一个经典问题：

```
CPU 看到的是 Cache 里的数据
DMA 操作的是真实 SRAM 里的数据
```

于是就可能出现：

### 情况 1：DMA 接收数据，CPU 读不到最新值

流程：

```
DMA 把新数据写入 SRAM
CPU 去读 buffer
CPU 读到的却是旧 Cache
```

解决方法：

```
SCB_InvalidateDCache_by_Addr((uint32_t *)buf, size);
```

意思是：
**让 CPU 丢掉旧 Cache，重新从 SRAM 读取 DMA 写进去的新数据。**

------

### 情况 2：DMA 发送数据，外设发出去的是旧数据

流程：

```
CPU 修改了 tx_buf
数据可能还停留在 DCache
真实 SRAM 还没更新
DMA 从 SRAM 取数据
DMA 取到旧数据
```

解决方法：

```
SCB_CleanDCache_by_Addr((uint32_t *)buf, size);
```

意思是：
**把 Cache 里的新数据刷回 SRAM，然后 DMA 再去搬。**

------

## 8. Clean 和 Invalidate 怎么记？

这个非常重要。

| 操作               | 中文理解                 | 用在什么时候                        |
| ------------------ | ------------------------ | ----------------------------------- |
| Clean DCache       | 把 Cache 写回内存        | CPU → DMA，例如 SPI/UART DMA 发送前 |
| Invalidate DCache  | 丢弃 Cache，重新从内存读 | DMA → CPU，例如 ADC/UART DMA 接收后 |
| Clean + Invalidate | 先写回，再丢弃           | 某些双向 DMA 或复杂场景             |

记忆方式：

```
CPU 写了，DMA 要读：Clean
DMA 写了，CPU 要读：Invalidate
```

------

## 9. DMA Buffer 推荐放哪里？

### 推荐 1：放 AXI SRAM

适合大多数 DMA 场景：

```
0x24000000 AXI SRAM
```

例如：

```
__attribute__((section(".RAM_D1"))) uint8_t dma_buf[1024];
```

### 推荐 2：放 SRAM1/2/3

也很常用：

```
0x30000000 SRAM1
0x30020000 SRAM2
0x30040000 SRAM3
```

尤其 DMA1/DMA2 挂在 D2 域，访问 SRAM1/2/3 比较自然。参考手册系统架构图中，DMA1/DMA2 位于 D2 Domain，SRAM1/2/3 也在 D2 Domain。

### 不推荐：DTCM

```
0x20000000 DTCM
```

CPU 用可以，普通 DMA 不要用。

------

## 10. 不同 DMA 的简单区别

STM32H743 里不止一个 DMA。

| 类型        | 简单理解           | 常见用途                              |
| ----------- | ------------------ | ------------------------------------- |
| DMA1 / DMA2 | 常规 DMA           | UART、SPI、I2C、ADC 等                |
| BDMA        | D3 域小 DMA        | 访问 SRAM4、Backup SRAM、部分 D3 外设 |
| MDMA        | 更强的内存搬运 DMA | 大块内存搬运、链表传输、配合外设搬运  |
| DMA2D       | 图形专用 DMA       | LCD、图像填充、颜色格式转换           |

参考手册中说明，MDMA 有 AXI 64-bit bus 和 AHB 32-bit bus，适合内存到内存传输；DMA1/DMA2 有 memory bus 和 peripheral bus；BDMA 位于 D3 域，访问范围限制在 D3 资源，比如 SRAM4、Backup RAM、AHB4/APB4 外设。

你现在普通嵌入式开发，重点先掌握：

```
DMA1 / DMA2 + DMAMUX + Cache一致性 + Buffer放置位置
```

MDMA、BDMA 后面遇到特殊需求再看。

------

## 11. 开发时最实用的检查清单

以后你调 DMA，按这个顺序排查：

### 1. 外设时钟开了吗？

```
__HAL_RCC_xxx_CLK_ENABLE();
```

没有开时钟，寄存器访问和外设工作都可能异常。

------

### 2. DMA 时钟开了吗？

```
__HAL_RCC_DMA1_CLK_ENABLE();
__HAL_RCC_DMA2_CLK_ENABLE();
```

------

### 3. DMAMUX 配对对了吗？

H7 的 DMA 请求通常要经过 DMAMUX。
外设请求没有接到正确 DMA Stream，就不会触发搬运。

------

### 4. Buffer 有没有放到 DTCM？

如果 DMA Buffer 在：

```
0x20000000 DTCM
```

普通 DMA 大概率有问题。

------

### 5. Cache 有没有处理？

DMA 发送前：

```
SCB_CleanDCache_by_Addr(...);
```

DMA 接收后：

```
SCB_InvalidateDCache_by_Addr(...);
```

------

### 6. 地址和长度有没有按 Cache Line 对齐？

Cortex-M7 DCache 常见 Cache Line 是 32 字节。实际使用时，DMA Buffer 最好做 32 字节对齐：

```
__attribute__((aligned(32))) uint8_t dma_buf[1024];
```

并且 Clean / Invalidate 的地址和长度也最好按 32 字节边界处理，否则可能影响旁边的数据。

------

## 12. 一句话总结

STM32H743 参考手册最该先提炼的不是具体外设怎么用，而是这条主线：

```
时钟决定外设能不能跑；
总线决定 DMA 能不能访问；
Cache 决定 CPU 和 DMA 看到的数据是不是一致。
```

最重要的开发经验是：

```
DMA Buffer 不要随便放 DTCM；
开 DCache 后，DMA 前后必须维护 Cache；
外设不仅要开总线时钟，还要注意 Kernel Clock；
H743 的 DMA 问题，很多不是代码逻辑错，而是内存区域 + Cache + 总线访问权限错。
```
